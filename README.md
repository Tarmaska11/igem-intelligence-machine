# iGEM Intelligence Machine

A search engine over every iGEM team project from **2008 to 2025** — 5 094 team-years.
Search by idea, chassis organism, molecular technique, biological part, target molecule,
result, or failure, and find the teams who already tried what you are about to try.

It is a plain website. There is no server and no install: open the page and search.
The whole archive is compiled into the page, so search runs in your browser and answers
in a few milliseconds.

**Live site:** https://tarmaska11.github.io/igem-intelligence-machine/

---

## What it's for

Every year teams spend weeks rediscovering that a promoter leaks, a chassis dies under
a load, or an assay never gives a clean signal — things a previous team already wrote
down and then let rot on a wiki that moved or went offline. This tool makes that history
searchable, including the parts teams usually bury: the `failure_modes` of every project
are indexed, so you can search for trouble on purpose.

## How to use it

Type a query. Narrow with the filters on the left — year, track, application area,
chassis organism, technique, target molecule, part, region, country, team section, and
whether the team documented failures. Click any result for the full structured record and
a link to the original wiki. The query and filters live in the URL, so a search is
shareable and the back button works.

## Running it locally

Any static file server works, because the site is just files:

```
git clone https://github.com/Tarmaska11/igem-intelligence-machine.git
cd igem-intelligence-machine
python -m http.server 8899
```

Then open <http://127.0.0.1:8899/>. No dependencies, no build step, no network needed —
the bundled archive in `baseline/` is the complete 2008-2025 dataset.

## Rebuilding the data

The website ships with prebuilt data. To build it again from the sources:

```
python pipeline/build.py             # the search bundles
python pipeline/build.py --fulltext  # also the wiki-text index (slow, ~10 min)
```

`pipeline/sources.json` says where the source summaries, the official iGEM team CSVs and
the scraped wiki text live. The build is deterministic: the same inputs give byte-identical
output, and every file is listed with its SHA-256 in `manifest.json`.

Python 3.9+, standard library only — `requirements.txt` is empty on purpose.

## How it is put together

```
index.html                  the page
assets/app.js               UI, routing, loading, fallback
assets/search.worker.js     BM25 search, runs off the main thread
assets/style.css
baseline/                   the 2008-2025 archive, gzipped JSON (8.7 MB)
pipeline/build.py           builds everything in baseline/
pipeline/canon.py           tidies the messy facet values into real filters
pipeline/teams_meta.py      joins the official iGEM team metadata
```

**Search.** Every project's summary, structured fields and team name go into one inverted
index. Ranking is BM25 with the field weights folded into the term frequencies, so a team
whose *core* molecule is mercury outranks one that merely mentions it. Terms are ANDed for
precision and fall back to OR when that is too strict.

`E. coli` is tokenised as `ecoli` as well as `coli`, and `CRISPR-Cas9` as `crispr`, `cas9`
and `crisprcas9`, so an abbreviation, a half, or the whole thing all find the same projects.

**Filters.** The summaries were written by language models, so the same thing is spelled
many ways — `Gel electrophoresis`, `gel electrophoresis` and `Agarose gel electrophoresis`
were three separate filters covering a third of the corpus each. `pipeline/canon.py` folds
them into one label at build time. Track, region, country and team section come from iGEM's
own team lists rather than from the summaries, and match 96.1% of records.

## Where the data comes from

Two sources, joined at build time:

1. **Structured project summaries** — one 16-field JSON record per team-year, generated by
   reading each team's wiki (see the AI note below).
2. **Official iGEM team lists** (`csv/teams-*.csv`, 2004-2025) — the authoritative name,
   region, country, city, section and village (track) for every team.

## Staying current after the competition

iGEM repositories are frozen after the competition deadline, which would normally mean the
archive stops at 2025 forever. So the site reads its content from a separate, unfrozen
repository:

**https://github.com/Tarmaska11/igem-intelligence-machine-db**

On load the page shows the bundled 2008-2025 archive immediately, then asks that repository
whether there is anything newer. New projects, blog posts, the year range, the counts in the
header and the extra page in the navigation bar can all be updated there without touching
this repository.

If that repository is unreachable, renamed, rate-limited, or serving something broken, the
page silently keeps the bundled archive. **There is no state in which the site fails to
load or fails to search.**

## A note on AI

The structured summaries were **generated by language models reading each team's wiki**,
not written by hand. This matters when you read a record, so it is stated plainly:

- **Models used**, counted from the built data (5094 records):

  | model | records | share |
  |---|---:|---:|
  | local `gemma-3n-E4B-it` (Q4_K_M) via llama.cpp | 4331 | 85.0% |
  | Google Gemini (CLI, no API key) | 326 | 6.4% |
  | GitHub Copilot (CLI) | 229 | 4.5% |
  | OpenAI Codex (CLI) | 204 | 4.0% |
  | Claude | 4 | 0.1% |

  Each record stores which model produced it, in the `ml` field.
- **Input:** the team's own public wiki text, scraped and cleaned. Nothing else was supplied,
  and no model was fine-tuned.
- **Task:** fill a fixed 16-field schema (problem, approach, chassis organisms, techniques,
  parts, target molecules, results, failure modes, novelty, references, summary).
- **Known limitations.** Summaries are extractive but not verified against the wiki
  sentence by sentence, so a field can be wrong or missing. Facet values are inconsistently
  spelled at source, which is why `pipeline/canon.py` exists — and that canonicalisation is
  rule-based, so an unusual spelling can land in the long tail instead of its proper group.
  Metadata for 3.9% of records could not be matched to an official iGEM team row. **Treat a
  record as a pointer to the wiki, not as a citable statement of what a team did** — every
  record links to its source.
- No AI model runs on the website. Search is BM25; there is no model in the page and no API
  key anywhere.
